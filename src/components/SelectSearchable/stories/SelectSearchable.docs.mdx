# SelectSearchable

A composable, searchable, and accessible select component that supports single and multiple
selection, custom triggers, and large option sets.

## SelectSearchable.Root

<div className="topLink">
  [Back to top](#top)
</div>

**SelectSearchable.Root** is the top-level component that manages state, focus, and accessibility for the select.

<details>
  <summary>Click to expand details</summary>

  SelectSearchable renders a visually hidden native `<select>` element for form submission and native integration.

  ### Controlled and Uncontrolled Values

  A defined `value` makes Root controlled. Omitting `value` or passing `undefined`
  makes it uncontrolled, with `defaultValue` providing the initial selection.
  Keep the same mode throughout the component's mounted lifetime; switching modes
  produces a development warning.

  To clear a controlled selection, use `''` in single mode or `[]` in multiple mode.
  Setting `value` to `undefined` switches to internal state and may restore an earlier
  uncontrolled selection; it does not clear the controlled value. If your application
  stores an empty selection as `undefined`, pass `value={value ?? ''}` or
  `value={value ?? []}` as appropriate. `null` is not a supported value.

  ### Focus Management

  SelectSearchable contains two internal focusable elements:

  - **Trigger** – `role="button"` (displays the selected value and toggles the listbox)
  - **Search** – `role="combobox"` (used to filter and navigate options)

  If no `Search` subcomponent is composed, the `Trigger` assumes the `combobox` role instead.

  ### Labelling

  Use one `Label` and one optional `Error` per Root. Give Search its own complete,
  localized name, for example `aria-label="Search people"`. Placeholders are separate
  hints and should not be used as a substitute for an accessible name.

  If you need manual control, you may provide ARIA attributes directly.

  The following attributes can be set on **Root** as shared defaults:

  - `aria-labelledby`
  - `aria-label`
  - `aria-describedby`
  - `aria-description`
  - `aria-errormessage`

  These attributes may also be provided directly on `Trigger` or `Search`.

  Naming uses exclusive precedence: local Trigger/Search naming, then Root naming,
  then Label. A source supplies either `aria-labelledby` or `aria-label`; if it
  supplies both, `aria-labelledby` wins. Empty or whitespace-only names fall back
  to the next source. Names from different sources are never concatenated.

  A local `aria-label` suppresses inherited `aria-labelledby`. Search falls back
  to the field name for compatibility, but a specific localized Search name is recommended.
  Translate complete strings in your application; the component does not prepend
  English words or extract text from Label to build a Search name.

  The searchable Trigger's default name includes the field name and visible trigger
  content (selection or placeholder). An explicit local Trigger name is a complete
  override; include the displayed selection in that name if appropriate. Decorative
  icons should have `aria-hidden="true"`. Custom trigger content is included as well.
  The select-only combobox retains its field name without automatically appending content.

  Local `aria-description` replaces the shared string. Local `aria-describedby`
  replaces the shared ID list, then the rendered Error ID is appended when invalid.
  An empty local description or ID list suppresses the shared default. Supplied text
  and ID lists are preserved, including repeated IDs. The automatic Error ID is added
  only if absent, and error IDs are excluded from descriptions when already referenced
  by `aria-errormessage`. Browsers prioritize
  `aria-describedby` over `aria-description`, so use the former for visible help text.

  ### Validation

  When `aria-invalid` is set on the Root:

  - Root owns invalid state, which is applied to both Trigger and Search.
  - A rendered Error is referenced through `aria-describedby` while invalid.
  - Explicit `aria-errormessage` remains that attribute, with local values overriding Root. It is omitted while valid, not converted to `aria-describedby`.
  - IDs used by `aria-errormessage` are excluded from `aria-describedby` to avoid attaching the same error twice.
  - Consumers must provide the elements referenced by explicit external IDs.

  ### Styling Invalid

  For styling invalid state, SelectSearchable exposes a `data-invalid` attribute on internal parts (e.g. Label / Trigger / Search / Dropdown / Error).  
  Prefer `data-invalid` as the consistent styling hook across interactive and non-interactive parts.

</details>

## SelectSearchable.Label

<div className="topLink">
  [Back to top](#top)
</div>

**SelectSearchable.Label** renders a native `<label>` element and automatically associates it with the SelectSearchable control.

<details>
  <summary>Click to expand details</summary>

  The Label:

  - Automatically links to the internal control via `htmlFor`.
  - Provides the fallback field name when Root or a subcomponent does not supply its own name.
  - Requires no manual `id` or `aria-labelledby` wiring.

  ### Controlled props (cannot be overridden):

  - `id`
  - `htmlFor`

  The `id` is generated by the Root and used internally to manage accessibility relationships.

  ### Accessibility

  When mounted, the Label registers itself with the Root so that:

  - Its ID supplies the fallback `aria-labelledby`.
  - Explicit Root or local naming replaces this fallback instead of merging with it.

  ### Styling

  Exposes `data-part='label'` and `data-invalid` for easy custom styling.

</details>

## SelectSearchable.Error

<div className="topLink">
  [Back to top](#top)
</div>

**SelectSearchable.Error** renders an error message associated with the SelectSearchable control.

<details>
  <summary>Click to expand details</summary>

  It wraps a native `<p>` element and automatically links itself to the control for accessibility.

  ### Controlled props (cannot be overridden):

  - `id`

  The `id` is generated by the Root and used to associate the error message with the control.

  ### Accessibility

  When its paragraph is rendered:

  - Its ID is appended to `aria-describedby` when invalid, unless the same ID is already used by `aria-errormessage`.
  - Hiding or unmounting the paragraph removes its automatic reference.
  - Screen readers can announce the error message when the control receives focus.

  ### Visibility

  If `hideWhenValid` is `true`, the component will not render when the control is valid.

  If preferred, you may instead conditionally render the component yourself based on validation state.

  ### Styling

  Exposes `data-part='error'` and `data-invalid` for easy custom styling.

</details>

## SelectSearchable.Trigger

<div className="topLink">
  [Back to top](#top)
</div>

**SelectSearchable.Trigger** renders the interactive control that opens and closes the dropdown.

<details>
  <summary>Click to expand details</summary>

  It wraps a native `<button>` element and forwards all standard `<button>` attributes **except** those managed by the Root context.
  When no `Search` subcomponent is present, the Trigger assumes the `combobox` role and handles keyboard navigation directly.

  ### Controlled props (cannot be overridden):

  - `id`
  - `type`
  - `disabled`
  - `role`
  - `aria-haspopup`
  - `aria-controls`
  - `aria-expanded`
  - `aria-activedescendant`
  - `aria-invalid`

  The Trigger uses the Root `id`, or a generated ID when none is supplied.

  ### Children

  `children` may be either:
  - A `ReactNode`, or
  - A render function receiving:
    - `selectedValues: string[]`
    - `selectedLabels: string[]`
    - `isOpen: boolean`
    - `multiple: boolean`

  `selectedValues` contains the currently selected option values.
  `selectedLabels` contains the corresponding resolved labels from the registry.

  ### Styling

  Exposes:
  - `data-part='trigger'`
  - `data-state='open | closed'`
  - `data-invalid`

  for easy custom styling.

</details>

## SelectSearchable.TriggerValue

<div className="topLink">
  [Back to top](#top)
</div>

**SelectSearchable.TriggerValue** renders the currently selected value (or a placeholder) inside the Trigger.

<details>
  <summary>Click to expand details</summary>

  It wraps a native `<span>` element and displays the current selection.

  ### Behavior

  - When no value is selected, it renders `placeholder` (default: "Select…").
  - In non-multiple mode, it renders the selected option label.
  - In multiple mode, it joins the selected labels with commas.

  ### Controlled props (cannot be overridden):

  - `children`

  The displayed content is derived from the current selection and cannot be manually provided.

  ### Styling

  Exposes `data-part='value'` for easy custom styling.

</details>

## SelectSearchable.Dropdown

<div className="topLink">
  [Back to top](#top)
</div>

**SelectSearchable.Dropdown** renders the floating panel that contains the Search and OptionList sub components.

<details>
  <summary>Click to expand details</summary>

  It wraps a native `<div>` and renders it in a portal (to `document.body`) so it can float above surrounding layout.

  ### Behavior

  - Positions itself relative to the Trigger and automatically flips **up** or **down** based on available viewport space.
  - Clamps its maximum height to the viewport (and becomes scrollable when needed).
  - Closes when the user scrolls outside of the dropdown.

  ### Controlled props (cannot be overridden):

  - `ref`
  - `aria-hidden`

  The dropdown `ref` is managed by the Root for focus and interaction behavior.

  ### Styling

  Exposes `data-part='dropdown'` and the following attributes for easy custom styling:

  - `data-state='open | closed'`
  - `data-placement='down | up'`
  - `data-owner='{triggerId}'`
  - `data-invalid`

</details>

## SelectSearchable.Search

<div className="topLink">
  [Back to top](#top)
</div>

**SelectSearchable.Search** renders the combobox input used to filter and navigate options.

<details>
  <summary>Click to expand details</summary>

  It wraps a native `<input type="text">` element and is responsible for listbox navigation and active-descendant behavior.

  ### Controlled props (cannot be overridden):

  - `role`
  - `value`
  - `defaultValue`
  - `autoFocus`
  - `aria-invalid`
  - `aria-expanded`
  - `aria-controls`
  - `aria-activedescendant`
  - `aria-autocomplete`

  The Search input is controlled by the Root context and manages its own combobox semantics.

  ### Behavior

  - Automatically focuses when the dropdown opens.
  - Updates the option filter as you type.
  - Uses `aria-activedescendant` to track the active option while focus remains in the input.
  - Keyboard navigation is supported via the standard combobox + listbox pattern.

  ### Accessibility

  - Uses `role="combobox"` with `aria-controls` pointing to the listbox.
  - Local naming replaces inherited naming. Supply a complete translated `aria-label` or an external `aria-labelledby`.
  - Local descriptions override shared defaults; the rendered Error ID is appended while invalid.
  - Root owns `aria-invalid`; Search exposes the same `data-invalid` styling hook.

  ### Styling

  Exposes `data-part='search'` and `data-invalid` for easy custom styling.

</details>

## SelectSearchable.OptionList

<div className="topLink">
  [Back to top](#top)
</div>

**SelectSearchable.OptionList** renders the listbox container that holds selectable options.

Option values use **first wins** within each OptionList, in both single and multiple
selection. Comparison is exact and case-sensitive. Later options with the same value
are ignored, regardless of React keys; they are not rendered, searched, or navigated.
The first option supplies the label and disabled state, even if a later duplicate is enabled.
If the supplied order changes, the new first occurrence wins.

In development, a console warning is emitted once per duplicate value per mounted
OptionList. Production silently applies the same first-wins policy. Duplicate values
do not throw. Duplicate labels with distinct values are supported normally.

Prefer stable database IDs as values, and keep React
keys unique and stable when mapping arrays. This policy deduplicates option rows;
it does not normalize duplicate entries in a consumer-supplied selection array.

<details>
  <summary>Click to expand details</summary>

  It wraps a native `<ul>` element and applies listbox semantics.

  ### Controlled props (cannot be overridden):

  - `id`
  - `role`
  - `ref`
  - `aria-hidden`
  - `aria-multiselectable`

  These attributes are managed by the Root context to ensure proper listbox behavior.

  ### Accessibility

  - Uses `role="listbox"`.
  - The `id` is generated by the Root and referenced by the combobox via `aria-controls`.
  - When the control is closed or disabled, `aria-hidden` is applied.
  - In multiple mode, `aria-multiselectable="true"` is set automatically.

  ### Styling

  Exposes `data-part='list'` for easy custom styling.

</details>

## SelectSearchable.Option

<div className="topLink">
  [Back to top](#top)
</div>

**SelectSearchable.Option** renders a selectable item within the OptionList.

<details>
  <summary>Click to expand details</summary>

  It wraps a native `<li>` element and automatically participates in selection, keyboard navigation, ordering, and filtering within the `SelectSearchableOptionList`.

  ### Required props

  - `value: string` – The value committed to the control when this option is selected.

  ### Controlled props (cannot be overridden)

  - `id`
  - `role`
  - `aria-selected`
  - `aria-disabled`
  - `aria-hidden`
  - `hidden`
  - `ref`

  The DOM `id` combines the owning listbox's ID with the encoded option value.
  Identical values in different selects have distinct IDs. Within a listbox, the ID
  stays stable when React keys change or another duplicate becomes the first occurrence.
  React keys control reconciliation independently of DOM IDs.

  ### Accessibility

  - Uses `role="option"` within the `listbox`.
  - Applies `aria-selected` when selected.
  - Applies `aria-disabled` when disabled.
  - Applies `aria-hidden` and `hidden` when filtered out.
  - Active state is managed via `aria-activedescendant` on the combobox.

  No manual ARIA wiring is required.

  ### Behavior

  - Clicking an option commits its value.
  - In `multiple` mode, selection toggles.
  - Mouse interactions do not steal focus from the Trigger/Search.
  - Automatically participates in filtering and keyboard navigation.

  ### Styling

  Exposes:

  - `data-part='option'`
  - `data-selected`
  - `data-active`
  - `data-disabled`
  - `data-hidden`

  for easy custom styling.

</details>
